# Hyprland

Hyprland from the `-git` package, pure Wayland session. There is no X11 session to fall back to.
XWayland is enabled and `xwayland-satellite` runs at startup, so `DISPLAY` is set but only reaches
XWayland clients.

## Check that the running compositor is the installed one

Compare commit hashes, never version numbers. The `Hyprland 0.xx.y` banner in `hyprctl version` is a
stale compile-time constant that stays put on builds tagged well past it, so it proves nothing. The
running commit is the prefix of `$HYPRLAND_INSTANCE_SIGNATURE`, and the installed one is the
`.g<short>` suffix of the `-git` pkgver.

```bash
run=${HYPRLAND_INSTANCE_SIGNATURE%%_*}
disk=$(pacman -Q hyprland-git | grep -oE 'g[0-9a-f]{7,}' | tr -d g)
case "$run" in "$disk"*) echo "match" ;; *) echo "skew: running $run, installed $disk" ;; esac
```

An upgrade under a running session leaves the two out of step until the next login, and the headers,
stubs and `hyprctl` on disk then describe a build that is not the one answering. Contradictions
between documented and observed behaviour usually mean this, not a bug. The same skew applies to the
kernel: if `/usr/lib/modules/$(uname -r)` is missing, the running kernel can no longer load any
module it has not already loaded, which breaks on-demand module users while leaving everything
already loaded working.

## The config is Lua, not hyprlang

The entry point is `~/.config/hypr/hyprland.lua`, a stow symlink into `~/.dotfiles`. It `require`s
the files under `animations/`, `display/`, `programs/`, `variables/`, `theme/` and `input/`. There is
no `hyprland.conf` anywhere, and almost every Hyprland snippet online is written in the old `.conf`
syntax and will not work here.

The authoritative API reference is `/usr/share/hypr/stubs/hl.meta.lua`, autogenerated from the
Hyprland source and shipped by the package. It is roughly two thousand lines of LuaLS annotations
covering every config key, event name, dispatcher and object. Read the relevant part of it before
writing config instead of guessing from documentation, and mind the skew check above.

Top-level `hl` functions: `config`, `bind`, `unbind`, `define_submap`, `device`, `monitor`, `env`,
`curve`, `animation`, `gesture`, `permission`, `window_rule`, `layer_rule`, `workspace_rule`,
`exec_cmd`, `dispatch`, `timer`, `on`, `is_key_down`, `version`, the `get_*` query family, plus the
`dsp`, `layout`, `notification` and `plugin` namespaces.

`hyprmod.lua` carries a `-- Generated by HyprMod` header and is rewritten by that GUI. Do not
hand-edit it. Put durable settings in the hand-written files and let HyprMod own that one.

## Autoreload only watches the entry file

`misc:disable_autoreload` is false, but the watcher covers `hyprland.lua` alone. Editing a `require`d
file such as `variables/permissions.lua` or `display/rules.lua` changes nothing until an explicit
`hyprctl reload config-only`, which reloads the config without reconfiguring monitors.

Permissions are a harder case still: a reload does not apply them at all. See below.

A half-written file or a Lua error hits the live session the moment you reload. Write config edits in
one atomic operation and check `hyprctl configerrors` straight after; it prints nothing when clean.

## hyprctl speaks Lua

`hyprctl dispatch` no longer takes the old string dispatchers. `hyprctl dispatch focuswindow
class:foo` fails with a Lua parse error. The current forms:

```bash
hyprctl dispatch 'hl.dsp.window.close()'
hyprctl dispatch 'hl.dsp.focus({ window = "class:kitty" })'
hyprctl repl '<lua>'     # evaluates and prints the returned value
hyprctl eval '<lua>'     # evaluates and prints only "ok"
```

Use `repl` whenever you need the result back. `eval` swallows it.

Dispatcher namespaces, verified at runtime:

- top level: `dpms`, `event`, `exec_cmd`, `exec_raw`, `exit`, `focus`, `force_idle`,
  `force_renderer_reload`, `global`, `layout`, `no_op`, `pass`, `release_input_capture`,
  `reload_config`, `send_key_state`, `send_shortcut`, `submap`
- `dsp.cursor`: `move`, `move_to_corner`
- `dsp.window`: `alter_zorder`, `bring_to_top`, `center`, `clear_tags`, `close`, `cycle_next`,
  `deny_from_group`, `drag`, `float`, `fullscreen`, `fullscreen_state`, `kill`, `move`, `pin`,
  `pseudo`, `resize`, `set_prop`, `signal`, `swap`, `tag`, `toggle_swallow`
- `dsp.workspace`: `change_id`, `move`, `rename`, `swap_monitors`, `toggle_special`
- `dsp.group`: `active`, `lock`, `lock_active`, `move_window`, `next`, `prev`, `toggle`

Dispatchers take a table, not positional strings. A dispatcher that matches nothing warns and does
nothing, which makes `window = "class:__nonexistent__"` a safe way to test a call shape without
touching a real window.

Lua globals set through `repl` persist across calls, and binds registered through it do fire. Their
callbacks run in a context whose return value you cannot read back, so observe a callback by having
it touch a file and then testing for that file, not by incrementing a global.

`hl.bind("code:N")` takes the **xkb** keycode, which is the evdev keycode plus 8. `KEY_F13` is evdev
183, so the bind is `code:191`. Getting this wrong produces a bind that registers correctly in
`hyprctl binds` and silently never fires, which is indistinguishable from the key not arriving.
Prefer keysym binds where one exists.

## Layout

Multiple outputs, one of them rotated, which puts part of the layout at negative global coordinates.
Workspaces are pinned per output and persistent, and window rules deliberately park applications on
particular outputs and workspaces, many of them floating and centred.

None of that is worth restating here because it changes. Read `display/monitors.lua` and
`display/rules.lua`, or `hyprctl monitors -j`, and follow the existing section comment banners when
adding a rule.

Custom tiling layouts live in `display/layouts.lua`, registered with `hl.layout.register(name, ...)`.
Hyprland exposes them as `lua:<name>`, and that prefixed name is what a workspace rule's `layout`
must use. The bare name silently falls back to dwindle with no config error. `hyprctl workspacerules`
does not print the `layout` field; check `tiledLayout` in `hyprctl workspaces -j` instead. Lua layout
state resets on every reload.

## Permissions are enforced, and only load at compositor start

`ecosystem:enforce_permissions` is true and `variables/permissions.lua` is explicit rather than
permissive. Screen capture is granted to the specific capture tools and portals, so screenshots work
with no prompt. Keyboard access is granted to named devices and denied by default.

**A permission change needs a full Hyprland restart. `hyprctl reload` does not apply it, by design.**
The wiki is explicit: "Permissions set up in the config are not reloaded on-the-fly and require a
Hyprland restart for security reasons." Restarting the device or the client that wants the permission
achieves nothing on its own. Testing a permission change therefore costs the user a logout and login,
so get the rule right before asking for one, and never conclude a permission is not the cause of
something from a reload-only experiment.

Rules are matched in file order, first match wins, which is why the catch-all `deny` sits last.

Permission types and what the `binary` field is matched against differ per type:

| Type | Default | `binary` matches |
| --- | --- | --- |
| `screencopy` | ask | the client's binary path |
| `plugin` | ask | the binary path, or the plugin path |
| `keyboard` | allow | the **device name**, not a binary |
| `cursorpos` | ask | the client's binary path |
| `input-capture` | ask | the client's binary path |

Read that file before assuming an input or capture tool will work, and treat any change to it as a
change to the user's live input security policy: ask first. See `driving-the-desktop.md` for what
already works without touching it.

Canonical reference: <https://wiki.hypr.land/Configuring/Advanced-and-Cool/Permissions/>. The wiki
moved from `wiki.hyprland.org`, and the permissions page lives under `Advanced-and-Cool`.

## Sockets and events

`$XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/` holds `.socket.sock` (the request socket behind
`hyprctl`), `.socket2.sock` (the event stream) and `hyprland.log`. To watch events instead of
polling:

```bash
socat -U - "UNIX-CONNECT:$XDG_RUNTIME_DIR/hypr/$HYPRLAND_INSTANCE_SIGNATURE/.socket2.sock"
```

`hyprctl clients`, `hyprctl activewindow` and `hl.get_windows()` return the titles of everything the
user has open, which is private. Query with a filter for the window you actually need
(`hl.get_windows({ class = "kitty" })`) and never dump the full list into a transcript.

## The rest of the desktop

A Quickshell-based shell provides the bar, launcher, control centre, notifications and lock screen. A
wallpaper daemon, a polkit agent, the portals, a clipboard persister, XWayland and several user
applications are all started from `programs/autostart.lua`. Keybinds in `input/keybinds.lua` toggle
the wallpaper and the shell off and on with the user's own `killall -9` logic, deciding from `pgrep`
whether each is running. Read that file rather than guessing, and do not kill any
of it yourself.
